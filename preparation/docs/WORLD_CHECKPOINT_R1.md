# 完整物理塔检查点 R1

本轮只开发和执行源码级检查，按要求没有构建或启动项目。下述恢复接触顺序尚未在原生 Box2D、Creator、Web 或微信真机中验收。

## 最小方案

`TowerWorld.exportState()` 深复制当前有效塔体与有限连接，`TowerWorld.restoreState()` 先校验完整数据，再重建对象；没有保存池化 contact 对象。只有一个短暂的 `restoring` 状态，用来等待原生承托接触重新建立。这里不管理历史快照、库存、广告或持久化文件。

是否需要更复杂方案：不需要通用回滚框架。一次恢复接触阶段是当前已有屏外隔离规则要求的：新世界还没有真实 contact 时，立即用空承托图判断会拒绝屏外塔底与原塔底重新接触。仅在首次重建期间保留快照中的承托资格及已有短暂回归资格，同时继续隔离原先已脱离的屏外物体，无须增加隐形支撑或把动态塔底固定。

## 保存内容与边界

- 所有 `!lost` 对象，包含屏外塔底、当前夹持物和未确认落物；保留 ID 空洞与下一个 ID。
- 深复制当前 ObjectSpec、位置、角度、缩放、placed、首次接触观察时间、释放死亡边界和深层阻尼值。动态对象取 native pose；夹持对象取 node pose，覆盖同帧拖动/旋转后立即释放时 native 尚未同步的情况。
- 真实刚体类型、睡眠许可、bullet、固定旋转、重力倍率、线性/角阻尼、碰撞组，以及 collider 的启用状态、密度、摩擦、恢复系数与 sensor。
- 正常安全边界、实际深层辅助参考和辅助开关。
- 篮球与木板现有有限连接的对象 ID、局部 offset、角度、力/力矩预算、correctionFactor、collideConnected；平台使用 ID 0。一次缓冲消费集合和木板已断连接集合随有效塔保存，防止恢复额外获得帮助。
- 尚未过期的原承托回归资格，只保存上/下物体 ID 与最多 0.12 秒的剩余时间；重建时映射新 collider 身份，剩余时间在恢复物理阶段继续消耗。它不能提供承托，只允许原本合法的低速、同承托面、真实向上接触重新进入 solver。快照的 supported 布尔只用于首步接触资格，完成后立即弃用。

池化接触、旧掉落集合、旧物体速度均不恢复。恢复后线速度/角速度归零；承托关系由真实 solver 接触及已保存的真实连接重建。完整 native 角度保留多圈信息，避免现有 joint 的 angularOffset 在重建时产生整圈误差。

## 恢复顺序

1. 在改动前验证所有对象参数、ID、边界、连接端点、重复连接和消耗集合；无效数据抛错，旧世界不变。
2. 先禁用/销毁旧 joint，再把旧记录标为 lost，禁用 collider/body 与节点后销毁，防止延迟销毁期间继续碰撞。旧 BEGIN/PRE_SOLVE/END 回调均不能进入新世界。
3. 重建全塔并归零速度，按原 ID 重建原连接，清空旧池化 contact。按原边界维持侧面越界、未确认下越界和已脱离屏外物体的接触隔离；只允许原承托资格和仍有效的同支撑低速回归。失落计时暂不推进，碰撞音效不发出。
4. 等至少一次实际 fixed step 的时间条件满足。Creator 3.8.8 即便没有执行 fixed substep 也会发出 AFTER_PHYSICS，因此只收到一次事件不足以解锁；累计有效 BEFORE_PHYSICS 时间严格大于 fixedTimeStep 后，于相应 AFTER_PHYSICS 恢复安全边界并重新计算真实支撑。
5. 控制器在 `restoring` 为 true 时保持输入、计分、抽取、演出关闭，完成后恢复正常流程。

`canSaveCheckpoint()` 拒绝恢复中、未稳定、有落物危险、侧面越界及未确认越下边界物体；已确认且真实承托的屏外塔底继续有效。控制器负责连续稳定时间、非 Critical、碰撞冲击和事故等上层条件。`exportState()` 不强制稳定，因为撤销必须记录实际释放前的轻晃状态。

## 已执行检查

`node preparation/tools/check_world_checkpoint.cjs` 执行真实 TowerWorld/ContactAssistance 方法，使用 Cocos engine doubles，14 组通过：全塔深复制、夹持同帧姿态、非法快照先验证、物理参数与零速度、连接及一次消费恢复、无 step 的 AFTER 不解锁、无 contact 不造支撑、旧回调隔离、安全资格、lost 省略与 ID 延续，以及回归资格的 ID/剩余时间重建、真实低速向上接触要求、原期限到期、首次重建隔离、非法资格不得改变旧世界。

这是源码调用与数据一致性检查，不证明原生接触重建、真实 joint 受力、复活手感或广告功能通过。后续实际引擎验证必须特别覆盖高塔屏外塔底、旋转连接、密集接触、长局恢复后的 RNG/高光，以及恢复失败路径。
