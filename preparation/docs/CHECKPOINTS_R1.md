# 稳定检查点与本地恢复内核 R1

2026-09-16。用户继续授权下一批开发，沿用暂不构建、不启动项目。本批实现 SPEC §6.6 在当前十二物体、导演、高光及事故规则中的状态恢复，不宣称后悔药或广告复活产品功能已完成。

## 最小方案与复杂度判断

现有 `TowerWorld`、`ContactAssistance`、`TowerDirector`、`RunHighlights`、`PlayView` 各增加直接的值状态导出/恢复，控制器持有两份内存检查点：最新合格稳定点和最近一次释放前状态。没有历史栈、配置、持久存档、跨版本迁移或通用回滚层。

两个检查点不能合并：晚于出物的稳定确认会不断替换稳定点，而撤销必须回到刚释放物体之前。恢复排队与物理重建互斥，用单一 `checkpointAction` 表示；世界内一次重建门禁是必要的，因为新实体尚无真实接触时不能按普通逻辑把屏外塔底判失效。已有篮球/木板约束、一次缓冲与断连资格属于当前已实现语义，必须恢复，不能只恢复坐标。

## 保存与调用

- 最近撤销点在真实 `release()` 之前同步保存，包含夹持物姿态和已显示 NEXT。自动释放和手动释放使用同一入口。
- 最新稳定点只在成功确认过物体后保存：真实稳定累计至少 0.65 秒、无事故/危险掉落或有效越界体、TowerRisk 非 Critical、近期冲击低于现有 2.4 阈值。合法、仍被承托的屏外塔底保留。
- 高度可以先按原规则确认；若当时检查点额外门禁不通过，继续保留旧点，之后真正合格再保存。普通 1.5 秒观察超时不强存。
- 每次成功放置仅更新到较新的合格稳定点，不在普通规划帧反复复制全塔。
- 当前仅有 `controller.restoreCheckpoint('stable' | 'undo')` 本地校准入口。返回 `true` 表示已排队，在下一有效 update 应用；无点、已结束、已有恢复请求或正在重建时返回 `false`。暂停时请求保留，普通恢复前台/取消暂停后才执行，不自动取消用户暂停。
- `controller.snapshot().checkpoints` 只提供点的件数/释放数/高度与排队/恢复状态，不暴露可随意篡改的完整快照。

这是本局内存功能，离开 HUD 后不保存。`HighlightState` 的初始反馈时刻为 `-Infinity`，直接值拷贝保留；本批不提供 JSON 往返、磁盘导入或任意外部快照加载接口。

## 状态覆盖

| 范围 | 保存的当前真实状态 |
| --- | --- |
| 塔体 | 所有有效 ID、nextId、当前 ObjectSpec、位置/角度/缩放、刚体和 Collider 必需值、placed、contactSeconds、原释放边界、辅助阻尼；包括屏外塔底与夹持物 |
| 接触辅助 | 真实篮球/木板有限连接的双方 ID、局部 offset、完整角度、力/力矩和连接参数；一次缓冲记录、已断连接、尚有效的同支撑短时返回资格 |
| 控制器 | 星数、放置/释放数、历史峰值、当前物体、规划剩余时间、旋转数、阶段、导演时间与事故计数、普通边界、校准模式 |
| 导演 | current/NEXT、seed/RNG、抽取次数、完整近期历史、稀有/救场/难度保护状态 |
| 高光 | 技术分与次数、已确认 ID、未确认释放的旧塔历史、危险恢复计时、反馈冷却和锁状态 |
| 镜头 | 普通 cameraY、targetCameraY、heldTop；尺寸/比例由当前安全区重新派生，事故 zoom 不恢复 |

动态体读取真实原生位置与完整圈数角度，防止 Node 在物理步中尚未同步。尚未释放的夹持体相反，以 Node 当前值为准，避免同帧拖动/旋转后松手保存到旧原生姿态。

## 恢复流程与边界

1. 在 update 中执行排队请求，清理旧音效、输入手指、事故和失败演出；暂停/音效/音乐设置保持用户当前状态。
2. 检查世界数据后先禁用并移除旧有限连接，退休旧刚体、禁用碰撞并销毁节点。旧 deferred 回调不能污染重用的 ID。
3. 按原 ID 和当前值重建全部有效体，线速度/角速度归零；恢复真实约束及已消耗/断连记录。保存的短时同支撑返回资格映射到新 Collider，不伪造或保留 pooled contact。
4. 等至少一个有效物理步重建真实接触；期间禁止输入、计分、抽取与碰撞声音。恢复首步保留原屏外接触资格边界；已脱离的屏外体不能趁恢复获得原本不允许的新支撑。随后按真实支撑图恢复普通安全判定与操作。
5. 不调用 spawn/handoff，不额外消耗 RNG。清掉旧物体视图、粒子、压缩形变和高光，重建普通镜头，按当前安全区配准；正在下降的物体保留原逻辑死亡边界，下一正常交接再更新。

撤销点使用后清空，晚于它的稳定点也失效，避免从被撤销的未来复活。重新释放会产生新的撤销点。撤销恢复至 planning 时给予完整 4 秒重规划窗口，否则自动释放保存的 0 秒会在下一帧再次释放；稳定恢复保持保存的倒计时。跨尺寸的 entering 恢复保留当前送入偏移，避免先落至终点再弹回。

零速度重建是 SPEC 指定的恢复方式，不是逐帧物理时间倒流。当前持续脱离/下坠计时从重建后重新判断；已有相同支撑的短时返回资格仅保留保存时余量，不增加新关系。纯音画事件不存档，也不补播。
