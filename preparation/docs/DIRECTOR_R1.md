# TowerRisk 与十二物体导演 · R1

2026-09-16：用户授权首页 R2 接入后继续推进开发、不再重复确认。本轮推进 Batch 2 的风险与导演最小子项；保留已有十二物体及前十四件开场。新增物体、高光、技术分、六道具与完整恢复均未在本专项实现。未启动项目，以下检查不代表引擎、主观手感或微信真机验收。

## 最小方案与对抗审查

复用控制器唯一 `spawn` 交接点，由一个纯 `TowerDirector` 保存 current、锁定 NEXT、种子与必要节奏计数；`TowerWorld` 只读输出六项物理风险信号，纯函数分类四档风险。无需新依赖、配置、队列、通用策略或新物体资源。

是否需要更复杂方案：不需要。两个明确需要新增的状态是种子 RNG 状态及未展示抽取所需节奏计数；仅用 `releaseCount % 14` 无法随机延伸、保证重复/救场间隔或复核同一 seed。物理支撑来源复用现有承托接触和有限连接，不另建支撑模拟。

对抗边界：

- 风险读取、诊断 snapshot 与每帧更新均不能消费 RNG；只有交接生成一个尚未展示的后继时才消费一次。
- NEXT 已展示后固定；事故幸存当前物体继续原阶段，不调用交接。失去当前物体且事故处理结束后，由原控制器交接一次。
- 开场按出物编号而非稳定放置数，延迟确认成绩不会延长保护期。明确校准模式仍使用调用者固定循环，绕开导演。
- 旋转风险采用距离最近正交静止面的偏角，合法横放及自然倒平不会永久锁定危险。翻倒过程仍由角速度、失去承托及悬空质量信号判断，不因角度靠近 90° 就整体归为 Safe。球体忽略倾角。
- Cocos `angularVelocity` 为 rad/s；物理采样乘 `180 / Math.PI` 后输入 deg/s。
- 支撑覆盖是基于真实承托关系的水平重叠比例，属于代理量，不宣称准确测得接触面积或重心稳定裕量。
- 风险只服务本轮导演，不修改既有高度或 `placed` 的稳定计分。SPEC §6.6 的非 Critical 条件用于后续稳定检查点保存，不能扩张为本轮普通计分门槛。

## SPEC 对应与参数边界

规范：`source-inputs/docs/zhynd_codex_handoff/SPEC.md` §3.3、§7、§7.1、§8.1。

- 已展示 NEXT 锁定。风险仅影响未展示后继，道具主动换物属于未来明确例外。
- 风险为 Safe / Unstable / Dangerous / Critical，参考倾斜、角速度/摇摆、接触支撑、大质量悬空、近期冲击及主支撑稳定性。
- 使用 SPEC 五个时间档难度初始权重：0–30 秒 55/35/10/0；30–90 秒 35/40/23/2；90–180 秒 20/40/35/5；180–300 秒 10/35/45/10；300 秒后 5/25/50/20。
- 荒诞维度独立分类，初值 Normal/Weird/WTF 为 45/30/25；在当前可用难度和荒诞组内归一，不能把 WTF 自动视为高难度。
- 同物体不相邻重复；连续两件 Hard/Chaos 后下一次未展示抽取使用 Easy/Normal；不连续三件 Rolling；前 90 秒屏蔽 Slippery→Rolling；最长七件非救场后，下一件强制 Platform/Rescue。
- 稀有候选鲸鱼抽取间隔至少八件；高风险 Rescue/Platform 权重乘四；Safe/Unstable 状态下实际稳定时间累计十八秒后 Danger 权重乘二。实际扣星事故后两次未展示随机抽取限定 Easy/Normal，并排除 Rolling/Slippery。

**SPEC 未定义具体风险阈值、逐物体分类、稀有间隔、恢复段长度或权重倍率。上述新增数字及分类均是本轮集中首测候选，不是已确认平衡结论。** 连续两件高难后直接限制到 Easy/Normal，是落实“明显提高”的保守首轮选择。

`RISK_THRESHOLDS` 的三列依次是进入 Unstable、Dangerous、Critical：

| 信号 | Unstable | Dangerous | Critical |
| --- | ---: | ---: | ---: |
| 距最近正交静止面的偏角（°） | ≥8 | ≥18 | ≥32 |
| 角速度（°/s） | ≥12 | ≥35 | ≥80 |
| 最小承托水平覆盖比例 | ≤0.45 | ≤0.22 | ≤0.08 |
| 无支撑质量占比 | ≥0.15 | ≥0.35 | ≥0.60 |
| 近期冲击（m/s） | ≥2.4 | ≥3.6 | ≥5 |

主支撑不稳定至少 Dangerous；多信号取最严重档。空塔明确 Safe，非有限数字保守 Critical。冲击衰减与有效游玩时钟由控制器维护；风险模块没有独立时钟。

控制器 `steadySeconds` 仅在 `world.isStable()` 且风险为 Safe/Unstable 时累计有效秒数，作为接口 `stableSeconds` 传入。普通短冲击或短暂未稳仅暂停累计；去除近期冲击后结构风险达到 Dangerous/Critical，或发生事故，则清零。此口径避免默认宽木板因保守覆盖代理长期标为 Unstable 而永远无法进入长稳节奏。抽取时若当前风险为 Dangerous/Critical，即使传入旧的十八秒以上稳定值也不会增加 Danger 权重。

现有十二件没有分类为 Chaos 的候选，故可用类别内归一该时间档权重，不虚构第二批物体或提前解锁规则。首次十四件仍优先按既有批准顺序输出，不因事故或危险改写；恢复倾向只能约束随机段。前八件没有冰块/篮球，第五/第六件已有荒诞物体机会。正常节奏提供早期荒诞机会，但首局前两件免倒计时可无限等候，因此不能宣称任意操作都严格在第 20–30 秒实际释放荒诞物体。

## 接口与状态

`classifyTowerRisk(TowerRiskSignals): TowerRisk` 是无副作用纯函数。输入为已发生接触且有效的动态塔体，包含尚未稳定确认和屏幕外物体，排除抓手中的物体、首次接触前自由落体及失效体。

`new TowerDirector(seed)` 立即给出第一件与第二件 NEXT。`current`、`next` 和 `snapshot()` 只读；`handoff({ elapsedSeconds, risk, stableSeconds, incidentCount })` 先将旧 NEXT 作为 current，再决定唯一的新 NEXT。种子使用完整 uint32，零为有效 seed；Mulberry32 每次随机选择只消费一次，固定开场不消费。相同 seed 与相同交接上下文可复核抽取，不承诺跨平台逐帧物理一致。

`incidentCount` 是实际扣星事故计数，不是仅发生趋势的上下文数；相同计数不会每次重置恢复段。诊断快照用于检查当前种子和节奏，不是完整存档或回滚接口，不能宣称 NEXT/RNG 恢复已完成。

## 本轮纯逻辑验证

命令：`node preparation/tools/check_tower_director.cjs`。

八组检查通过：风险六信号与边界/非法数值；前十四序列及前八限制；同 seed 重现和不同读取频率 RNG 不变；NEXT 锁定及事故后交接；128 个 seed × 400 件的重复/高难/滚动/救场/稀有/早期组合约束；事故仅影响两次未展示随机抽取；权重方向对照；Unstable 长稳可加难且 Dangerous/Critical 不受旧稳定时长加难。

固定 seed 样本中的 20,000 件随机抽取对照：普通 Safe 的救场 3,979 件，高风险 7,342 件；普通 Danger 7,769 件，持续安全后 10,074 件；20 秒档 Hard 1,923 件，500 秒档 Hard 9,484 件。这些计数仅验证权重方向，不是玩家难度、事故率或成功率。

本脚本内存转译并执行实际源模块，不依赖复制的规则实现、不生成构建文件、不启动 Cocos/浏览器/服务器。控制器与物理采样另由接入专项静态/模拟检查验证；真实物理长局、危险反馈和主观体验仍待后续验收。

项目源代码检查 `tsc --noEmit --skipLibCheck --pretty false` 通过；直接省略 `skipLibCheck` 时由当前 Cocos 引擎声明中的既有 WebGPU/JSB 等缺失类型报错，未更改项目配置。
