# 高光与技术分 · R1

2026-09-16：用户已授权继续推进开发、不再重复确认，本轮明确暂不构建。该专项实现 Batch 2 的四类高光判定与技术分；源码检查不代表真实物理、画面、音效、微信设备或参数平衡验收。规范来源为 `source-inputs/docs/zhynd_codex_handoff/SPEC.md` §10.2、§10.4、§11/11.1。

## 最小方案与复杂度判断

最小方案：一个独立于 Cocos 的 `RunHighlights` 管理本局积分、四类次数、危险 episode、未确认释放的必要旧塔历史和已确认 ID。物理世界只读提供真实承托几何；控制器在真实稳定确认节点结算并传递反馈，失败时锁定结果。无需事件总线、缓存层、额外计分框架、通用回滚、配置文件或新音频资源。

是否需要更复杂方案：不需要。释放记录必须保留释放当时的旧塔 ID 和风险，否则晚于出物的稳定确认会把同时确认的新物体当成旧塔、把事故幸存件误报为救场；已确认 ID 用于保证同一物体不可反复计分。惊险恢复属于塔体的一次危险过程，不一定伴随新物体，因而独立于物体确认记录，只有一个待恢复状态。反馈冷却与积分分开，是为了避免静音或特效限流漏记真实成绩；不建立排队补播。

## 首轮资格与候选参数

**SPEC 给定事件名称及完美落点不计分的边界，没有给定分值、危险持续时间、几何阈值、救场物体尺寸或高光冷却。以下数值全部是集中在 `HIGHLIGHT_TUNING` 的首轮候选，未经真机/长局标定，不是已确认平衡结论。** `stableSeconds` 复用既有真实稳定时长 `STABLE_SECONDS = 0.65`，不修改物理或原高度/放置数计分规则。

| 事件 | 资格 | 候选技术分 |
| --- | --- | ---: |
| 惊险稳住 | 至少两件已确认且有效的旧塔；其结构风险连续 Critical ≥0.35 秒；随后旧塔与全塔都恢复 Safe/Unstable，并连续真实稳定 ≥0.65 秒；期间无事故或扣星 | 100 |
| 极限边缘 | 新确认物体受到真实承托；仅一个独立承托者，承托点跨度覆盖为自身宽的 0.15–0.35；重心相对承托区中心的偏移 / 半跨度为 0.65–1 | 80 |
| 桥接成功 | 新确认物体受到至少两个独立物体的真实向上承托；重心两侧承托区间的净空 / 自身宽 ≥0.12；承托点跨度并集 / 自身宽 ≥0.15 | 120 |
| 大物体救场 | 释放时至少两件真实旧塔处于 Dangerous/Critical；自身宽 ≥140 世界单位（1.4u）且宽×高 ≥20,000 世界单位²（2u²）；确认时全塔及旧塔恢复 Safe/Unstable 并真实稳定；此物体当前直接承托至少一件释放时已经确认的旧物体 | 150 |

极限边缘和桥接只要求真实物理稳定，不额外要求风险为 Safe/Unstable。风险的保守覆盖代理可能让一个实际稳定的偏窄支撑保持 Dangerous，不能因此改变既有稳定确认或屏蔽所有边缘事件。

每个新确认物体最多计一个物体类高光，固定优先级为桥接 → 极限边缘 → 大物体救场，不叠加三个分值。惊险稳住是独立的危险过程，真实恢复时最多计一次；因此一个真实桥接确认与一次旧塔危险恢复可以同帧成立，但同一 body/episode 都不可重复计分。

普通与完美落点没有正式事件类型、分值、计数或结算字段。技术分是辅助成绩，公式不向玩家暴露。

## 真实证据与保守边界

- 危险恢复采样使用此前已经确认的 `placed` 有效塔体，排除近期碰撞冲击和当前新落体；不是把导演的全塔风险直接当恢复资格。全塔/旧塔持续时间由有效游玩 `dt` 累计，每次最多 0.067 秒。新物体自己的旋转、落地冲击、短暂 Critical 尖峰和单件塔不构成惊险事件。
- `oldTowerRisk` 中采样主体是旧塔，沿真实向下支撑路径保留承托它的新物体；独立落在地面且不支撑旧塔的新物体不污染旧塔根部稳定性。自由落体首次接触前的刚体不提供虚构承托。
- 桥/边缘采用真实 solver 的向上承托关系与接触点水平跨度；重复 fixture/contact 不增加独立承托者数量。覆盖是这些点跨度并集除以自身宽，不是图像像素覆盖，也不是精确三维接触面积。只有一个 solver 点而无可证明跨度时保守不报边缘；接触点分布和形状仍需后续物理场景校验。
- 仅左右 AABB 重叠、侧碰或两个接触点来自同一物体，不足以证明桥接。桥接要求不同承托者在重心两侧形成真实净空。
- 大物体救场只认可它直接向上承托释放前旧物体。普通大物体仅落在危险塔上，即使后来稳住，也不会自动记为救场。采用宽×高只是本轮尺寸候选，不声称是精确轮廓面积或实际质量阈值。
- `recordRelease` 复制并去重旧塔 ID，后续新增已确认体或调用者数组变更不能重写历史。重复注册同一物体不能改变风险和旧塔历史。

## 接口和调用顺序

`recordRelease(id, { large, oldTowerRisk, oldBodyIds })` 在实际释放时调用；新释放清零稳定/恢复累计，保留已发生的旧塔危险过程。未注册释放的物体不能产生物体类高光。

`observe({ dt, oldTowerRisk, towerRisk, hasExistingTower, stable, incidentActive, incidentCount })` 只推进观察状态，不发成功事件。其中 `hasExistingTower` 表示至少两件已确认有效物体；`incidentCount` 为实际扣星事故累计数。暂停/后台不调用此方法。`dt=0` 的事故回调仍立即取消危险过程和所有待确认释放资格，避免物理回调在下一帧前发生事故而留下旧资格；零/负/非有限时间不能累积稳定或危险持续时间。

`confirmStable(placements)` 只在原有 `confirmStable` 达到真实稳定时调用；普通观察 1.5 秒后的出物节点不得调用。候选中同 ID、后续重复回调、已确认物体位置改变都不再计分。即使候选数组为空也要在控制器的“没有新增确认”提前返回前调用，才能结算旧塔自身恢复。

`HighlightPlacement` 提供 `id`、`supported`、`supportRatio`、`centerOffsetRatio`、`bridgeGapRatio`、`bearingCount` 和此物体直接承托的 `supportedBodyIds`。未证明的几何值不应伪造合格数据；不合法比例、非有限数据、失效支撑不会生成几何事件。

返回事件为 `{ kind, bodyId, points, feedback }`。`feedback` 表示音画可播放，候选间隔为 6 秒有效游玩时间；一次晚确认多个物体时可以全部正确计分，但同帧最多一次音画反馈。静音、反馈播放失败和冷却均不回滚积分，不在冷却后补播过期事件。

`snapshot()` 是无副作用诊断快照，复制各事件计数；反复读取不会推进时钟、消费资格或改变结果。`lock()` 在失败锁定瞬间调用，此后释放、观察、确认及倒塌余韵均不改变技术分、次数和内部计时。该对象不是撤销/复活存档接口，不能据此宣称完整恢复已经完成。

## 本轮验证

命令：`node preparation/tools/check_run_highlights.cjs`。脚本在内存转译并执行实际生产模块，不复制一份规则，不生成构建产物，不启动 Cocos、服务器或浏览器。

23 组纯规则检查通过，覆盖：普通/完美落点不计分；真实稳定时长；同危险过程一次和后续新过程；Critical 短尖峰、落地冲击/新物体风险及单件旧塔排除；两种风险必须恢复；旧塔消失取消；暂停/长恢复帧；含零时长回调的事故与扣星取消；事故结束同步后允许同帧真实释放；读取无副作用；桥接独立支撑与真实净空；边缘偏移和宽板中央承托反例；稳定几何不被保守 Dangerous 风险屏蔽；非法几何；大物体直接救旧塔和反例；释放历史不可改写；多物体晚确认、优先级、去重；普通确认不能事后补记高光；物体与独立 episode；冷却独立于计分且无补播；新释放不借前次稳定时间；失败冻结；非法/未注册 ID。

控制器/物理世界/结算展示的接入证据由本轮总验证记录汇总。本专项未启动或构建项目；真实触发频率、桥接接触点可靠性、窄支撑误差、音画节奏、性能、长局难度及微信真机体验仍未验证。六道具、完整稳定检查点、后悔药与复活恢复属于后续开发范围。
