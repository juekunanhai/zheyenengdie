## 引擎与物理

- 基线：Creator 3.8.8。官方发布页可查：[Creator 下载](https://www.cocos.com/creator-download)。安装结果见 READINESS.md，不能仅凭下载成功认定环境可运行。
- 2D 后端：Box2D WASM，使用引擎固定 1/60 秒步长，最多 4 次追赶作为首轮测量起点。引擎属性名称与配置 schema 必须以安装的 3.8.8 文件为准；不能写一套自定义 profile 冒充实际启用。
- 使用引擎唯一自动步进；不在 update 内再手动 step。暂停和后台时暂停物理，恢复时通过公开 PhysicsSystem2D.resetAccumulator() 舍弃异常累积时间；已在安装版源码和本地运行中核实。
- PTM 是引擎内部转换，不能拿图片像素或物理米直接记分。[官方 2D PhysicsSystem 文档](https://docs.cocos.com/creator/3.8/manual/zh/physics-2d/physics-2d-system.html)说明默认固定步长及内部 32 PTM。
- 允许自然休眠；不能将屏外塔体改静态、固定旧角度、删除旧塔或新建底托。

### 安装版源码与现有配置

3.8.8 安装包的 `engine/editor/engine-features/render-config.json` 含 `physics-2d-box2d-wasm` 选项，项目已选择该模块。`app.asar/builtin/project/package.json` 的 profile 定义确认 designResolution、gravity、fixedTimeStep、maxSubSteps 等实际字段；项目已据此建立 settings/v2/packages/project.json，后续 R6 静态构建通过；本轮不修改该配置。

`physics-system.ts` 的构造函数读取项目 gravity 后乘 PTM=32，而运行时 `PhysicsSystem2D.gravity` setter 将传入值除以 32 才送入 Box2D。因此配置里的 y=-31.25，对应运行时 setter 的 y=-1000 世界坐标单位/s²，也就是当前换算的 -10u/s²。不能把 -31.25 同时传给运行时 setter。现有 API 注释与内部字段表达易混淆，交接以此实际调用链为准。

`maxSubSteps` 只限制每帧子步数，不主动丢弃累积时间。3.8.8 提供公开 `resetAccumulator()`；当前在暂停/恢复以及超过子步预算的一帧完成物理后调用，保留唯一自动步进。已验证 450ms 短卡顿后倒计时不持续追赶；没有访问私有 accumulator，也不宣称长局所有卡顿情境已覆盖。

Box2D WASM 实现包含 PRE_SOLVE 和 contact.disabledOnce，源码在事件发出后调用 ContactSetEnabled(false)，具备求解前阻止接触的接口依据。它不证明业务越界识别已正确；多子步时 Sprite/Node 位置可能尚未同步，判定必须使用可靠的物理位置或预测结果，仍需 1B 场景验证。

3.8.8 WASM 的 getLinearVelocityFromWorldPoint 将结果乘 PTM=32，返回世界单位/s；linearVelocity getter/setter 则直接读写 Box2D 速度。R4 的接触缓冲显式换算，额外限制平动修正以免旋转接触导致反向加速。FixedJoint2D 的 WASM 默认 referenceAngle=0 不满足保留落下倾角的要求；当前使用 RelativeJoint2D，明确设置以 base 刚体为基准的局部偏移和相对角度，避免 autoCalcOffset 的世界坐标差与旋转支撑不一致。

Sprite 等比缩放；模型朝向、Sprite 锚点、抓手挂点、Collider 形状与重心分别校准。宽高比不符时检查透视与美术缺边，不非等比拉伸凑比例。木板需先校准斜向原画的局部方向，不能直接把外接矩形当细长木板 Collider。

纸箱、木板、冰箱已采用获接受的修复 Sprite；其视觉批准不等于物理贴合通过。三态展示、旋转安全距离及四类指定落地行为已在 1A 检查；全朝向的透视边缘贴合和手机手感仍需试玩。候选数据见 ../calibration/GEOMETRY_CANDIDATES.json。

## 全塔模拟的对抗式审查

1. **同一步内越界又撞塔底**：仅在物理步结束后销毁，会先施加错误冲量。Batch 1B 必须验证步前预测与 contact 禁用的实际引擎时序。根据 swept Collider 与逻辑边界决定失效，并在碰撞求解前过滤；节点销毁放安全阶段。若 3.8.8 当前后端无法满足时序，不得用“下帧删掉”冒充解决。
2. **镜头上移误杀旧塔**：旧物体进入屏外不是 loss。需与起始平台支撑连通、脱离后持续下落的证据；支撑判断不能把侧面碰触或短暂相撞当作承重连接。
3. **阻尼制造悬浮**：仅对仍有有效支撑的深层旧塔施加距离加权角阻尼。自由下落立即排除；保持质量、位置、旧偏角和偏心几何。
4. **把平滑辅助误称完整算法承诺**：权重随深度增加只保证辅助曲线变化；无法保证任何塔的坏摆放影响严格单调衰减。Batch 1B 用同一初始结构、同一投放序列对照辅助开/关，测顶部位移、角速度和倒塌频率。阻尼若不能达到目标，再评审更复杂力矩方案。
5. **缩放救命或放大损失**：事故开始冻结边界、N 与 K；镜头拉远后不能重新计算。N<3 不走数量失败，否则 K=clamp(ceil(0.6N),3,6)。只计固定集合中已确认失效的唯一旧物体。
6. **事故永远不结束**：普通观察 1.5 秒上限不适用于仍在处理的明确掉落、高速下坠或事故。若趋势/支撑判断进入不收敛状态，应记录诊断和暂停安全处理，不能暗自刷物、补星或删除有效塔；同时不能把普通轻晃无限当成事故。完整算法收敛在 Batch 1B 实测。
