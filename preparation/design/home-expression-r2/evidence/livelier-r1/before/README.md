# 眨眼与抓握动作小样 R2

用户已确认先重做独立动作小样。此目录不属于游戏运行资产，不修改 Cocos 场景、玩法或微信构建；首页仍以原工程版本为准，替换要等本小样审核后再做。

## 为什么重做

R1只验证了坐标、触发与生命周期，用户明确退回自然度。两张表情开关、整臂旋转和淡入淡出缺少连续动作，不能把技术检查通过当作角色表演合格。

| R1 问题 | 本小样采用的修正 |
|---|---|
| 直接切到另一张笑眼图 | 原眼球与眼角不缩放，连续眼睑遮挡和重新睁开 |
| 手臂从球头连接处淡入，整个旋转 | 根部藏在马桶侧后，手肘、前臂、掌指分段改变姿态，收回遮挡处 |
| 手指只换两张图，像在摸前板 | 掌心落在箱盖，手指跨过前沿，握持时停住、松开后收回 |
| 箱子独立定时换脸 | 接触之后才出现短促局部眼睑回应 |

## 最小实现

使用少量生成关键素材、用户授权的本地配准与像素处理，离线生成连续局部姿态。播放器仅按源像素坐标合成图片序列；不添加骨骼依赖、通用动画系统、玩法逻辑或新的物理状态。

鸭子闭合快、睁开稍慢，一次约225毫秒。手部序列以24帧/秒播放，先从原马桶遮挡后探出，掌心接触箱盖再收紧、停留、松开，最后藏回。箱子的回应安排在接触之后，保持身体与其它五官位置。

[查看小样](index.html)。先看375×667手机尺寸的正常速度，再用0.5倍、暂停和进度条检查局部；放大图用于看接缝和遮挡，不作为正常游戏观感的替代。浏览器页面不是Cocos引擎验收，现有开始/设置图片在此仅用于还原构图。

## 来源与复现

- `face/`：原图、内置 image_gen 实际提示词与生成源、连续眼睑脚本、PNG和manifest。
- `hand/`：内置 image_gen 生成的手部关键素材、实际提示词、离线姿态脚本、PNG序列和manifest。
- `assemble_sequence.py`：按两份manifest生成本小样的`sequence.json`，不写入运行目录。
- `sample.js` / `sample.css` / `index.html`：独立审阅播放器。场景素材复用项目`assets/batch0/art/`正式原图。
- `capture_sample.cjs`：独立无头浏览器抓取实际Canvas画面和正常/慢速录屏；校验338个生产输入未变。
- `BASELINE.json`：本轮开始时的生产代码/素材/配置哈希。

实际生成提示词：[眼睑](face/prompt.txt)、[手部](hand/prompts.json)。均使用内置 image_gen；生成源与用户授权的本地修整脚本保留在对应目录。

当前状态和本轮自查结论记录在 [evidence/REVIEW.md](evidence/REVIEW.md)。小样未获用户确认前，不沿用R1“已通过”作为自然度结论。
