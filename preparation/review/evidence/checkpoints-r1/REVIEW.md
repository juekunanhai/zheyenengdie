# 稳定检查点与本地恢复内核 R1

2026-09-16。本批已完成当前十二物体玩法的内存检查点、撤销及稳定点恢复内核，供现有控制器本地校准调用。按用户要求没有构建或启动项目；源码检查通过不等于原生物理、画面或设备验收通过。

## 本批交付

| 改动前 | 改动后 |
| --- | --- |
| 只有当前运行状态，无法恢复既有塔体和进度 | 自动保留最新合格稳定点、最近一次真实释放前状态 |
| 仅恢复位置会丢掉有限连接、消耗记录和导演历史 | 恢复所有有效物体、真实篮球/木板连接、当前成绩、高光、普通镜头及已锁定 NEXT/RNG |
| 重新创建物体时，空接触图会误判屏外塔底 | 等待实际物理步重建接触，保留原首步资格与同支撑短时返回资格，继续隔离无资格屏外体 |
| 老视图、粒子与延迟音效可能残留 | 清除旧视图、形变、高光、事故演出及正在加载/播放的音效，恢复后按当前状态继续 |

最小方案是在现有类增加直接值状态导出/恢复，控制器保存两份快照，以一个互斥状态处理排队和物理重建。稳定点和释放前撤销点代表不同时间，不能合并；没有增加历史栈、持久化、配置或通用回滚框架。

稳定点必须满足连续真实稳定、无事故/危险掉落或有效越界物体、非 Critical 和低冲击条件。原有放置计分不受新增保存门禁影响；普通观察超时不能强行存点。撤销恢复后清掉该撤销点及已放弃未来的稳定点，防止重复计分。自动释放后撤销给予完整 4 秒重规划时间。

调用入口是 `controller.restoreCheckpoint('stable' | 'undo')`，只用于本地校准，尚未接入玩家按钮。当前既无六道具库存，也无后悔药扣减、广告授权或复活次数逻辑；本批不能视为完整后悔药/广告复活功能。详细状态和边界见 [检查点规则](../../../docs/CHECKPOINTS_R1.md)、[物理恢复](../../../docs/WORLD_CHECKPOINT_R1.md)。

## 对抗审查及修复

- 同帧拖动/旋转后立即释放，原生刚体尚未同步：夹持物改为保存 Node 当前姿态，动态体仍保存 native 完整姿态和角度。
- 自动释放保存的规划时间为 0：撤销恢复给予 4 秒重规划，避免下一帧立即再次释放。
- 跨尺寸恢复送入动画：重配夹持位置时保留当前送入偏移，避免先落终点再弹回。
- 刚脱离的旧屏外体恢复后丢掉合法短时重接触机会：保存原支撑 ID 与剩余 TTL，映射新 collider，仍要求真实向上法线及低相对速度。
- 恢复首步原本会放开新屏外支撑：保留原边界和承托资格作首步过滤，禁止已脱离屏外体获得新支撑。保存的资格不进入实时支撑图，结束后由真实接触和既有连接计算。

以上均补了对应源码回归；另一代理已对最后两项独立只读复核，未发现可证明的遗留问题。
